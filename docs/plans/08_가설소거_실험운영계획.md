원본 ZIP과 SHA-256을 보관한다. 단순히 파일을 다시 올리는 것은 최고점 보존과 다르다. 최종 제출 선택·점수 누적 방식은 아직 확인이 필요하다.

## 사용자의 제안에서 채택할 것과 바꿀 것

**채택:** 전략을 먼저 목록화하고, 하나의 가설만 바꾼 제출로 비교하며, 성공한 변경을 다음 기준점에 반영한다.

**수정:** `실험 → 같은 최고점 ZIP 재제출 → 실험`을 매일 반복하지 않는다. 평가가 결정적이고 제출 선택 규칙상 복원이 필요하지 않다면 동일 ZIP 재제출은 새 정보를 주지 않는다. 기본 운영은 **실험 3개, 이긴 파일을 로컬 최고점으로 즉시 등록**이다. 새로 조합한 최고점 파일은 아직 서버에서 검증받지 않았으므로 별도 후보이며, 그 조합의 공식 평가에는 슬롯을 쓴다.

예외적으로 같은 최고점 파일을 다시 내는 경우는 서버의 재현성 이상, 코드/의존성 변경 뒤 점수 재현 검증, 또는 마지막 제출이 최종 평가 대상이라는 규칙 때문에 복원이 필요한 경우다. 규칙 확인 전에는 안전장치가 필요 없다고 단정하지 않는다.

가능한 전략은 무한하므로 전체 조합을 완전 탐색하지 않는다. 아래 주요 축을 관리하고, 실패의 원인이 설명되거나 새 데이터·구조가 생긴 경우에만 재개한다. 최고점 도달 보장이나 전역 최적점 탐색 보장은 하지 않는다.

## 무엇을 소거하는가

소거 단위는 **아이디어 이름이 아니라 기준 모델 + 구현 + 설정 + 검증 조건**이다.

- ZB 하락은 `RAFT + 경계 평활화 + 조향 평활화 + 첫 프레임/정지 처리` 묶음의 하락이다. RAFT 전체를 영구 폐기할 근거가 아니다.
- ZD 상승은 차량 추적 파이프라인의 상승이다. 숨은 평가 영상에서 `entry_frame`과 `entry_side` 중 무엇이 이득을 냈는지는 아직 모른다. 공개 5개에서 방향이 같았다고 비공개에서도 같았다고 추정하지 않는다.
- 과거 로컬 시험만 실패한 후보는 `로컬 열세`, 실제 제출에서 진 후보는 `해당 구성 공식 열세`, 여러 요소가 섞인 경우는 `원인 미분리`로 구분한다.
- 한 번의 공식 점수 차이에서 통계적 유의성이나 Private 일반화를 확정하지 않는다. 집계 점수만으로 신뢰구간을 만들지 않는다. 같은 결정적 파일을 반복 제출하는 것으로 표본 불확실성이 줄어들지도 않는다.

상태는 `미검토 → 로컬 준비 → 제출 대기 → 공식 승리/동률/열세/실행 실패 → 채택/보류`로 관리한다. 실행 실패는 모델 가설 실패와 구분한다.

## 다음 제출 가능일의 3개 슬롯

아래는 **계획이며 아직 제출용 ZIP을 만든 것은 아니다.** 오늘 남은 제출이 있다는 가정도 하지 않는다. 파일 제작 시 공식 결과를 받은 기준 ZIP에서 출발한다.

| 슬롯 | 후보 | 바꾸는 것 | 비교 대상·해석 |
|---|---|---|---|
| 1 | E01: ZD에서 방향만 기존으로 복구 | 추적의 `entry_frame`은 유지, `entry_side`는 YY 방식 | ZD 대비 추적 방향의 한계 기여; YY 대비 추적 시각의 기여 |
| 2 | E02: ZD에서 시각만 기존으로 복구 | 추적의 `entry_side`는 유지, `entry_frame`은 YY 방식 | ZD 대비 추적 시각의 한계 기여; YY 대비 추적 방향의 기여 |
| 3 | E03: 그때 최고인 Stage 2 + Stage 3 경계 평활화만 수정 | Farneback·조향·정지 규칙 고정, Stage 3 전용 평활 함수만 교체 | ZB의 복합 실패에서 시간 경계 처리의 효과 분리 |

E01/E02는 독립 분석을 위해 **둘 다 동일한 ZD에서 분기**한다. E01 결과를 보고 E02의 다른 설정까지 바꾸지 않는다. 공개 검증에서 두 후보의 변화가 없으면 먼저 추가 공개 영상으로 발동 여부를 확인한다. 그래도 분리 효과를 관찰할 근거가 없으면 무조건 슬롯을 쓰지 않고 S2-02/S2-03으로 교체한다. 공개 출력이 같다는 것만으로 비공개에서도 무효라고 단정하지 않는다.

E01/E02 중 하나가 ZD보다 높으면 해당 파일을 최고점으로 채택한다. 둘 다 낮으면 ZD 유지. 둘의 변경을 결합한 것은 이미 ZD이므로 그 조합을 다시 제출할 필요가 없다. Stage 2 점수만으로 내부 항목별 정확도를 역산하지 않는다.

E03에는 슬롯 1/2까지 공식 검증된 최고 Stage 2를 포함한다. 따라서 E03이 성공하면 그 파일 자체가 새 통합 최고점이다. 별도의 ‘최고점 재제출’ 슬롯은 필요 없다. E03이 실패하면 직전 최고점 파일을 보관한다.

## 그다음은 결과에 따라 분기

- **진입 시각이 이득의 중심:** S2-02 접근 시작 대체 규칙, S2-03 역방향 추적을 각각 제거해 본다. 도움 되는 분기는 유지하고 손해 분기를 줄인다.
- **방향이 이득의 중심:** S2-04 상대 차량 선택과 화면 좌우 근거를 먼저 검토한다. 시각 문턱을 계속 조정하지 않는다.
- **시각·방향 모두 필요:** ZD 구조를 유지하고 추적 연결·차량 선택 중 하나를 개선한다.
- **경계 처리 승리:** 그 수정만 기준에 넣고 S3-02 조향 평활화 단독 실험으로 간다.
- **경계 처리 열세:** 기존 시간 처리를 유지한다. 이후 RAFT 단독 또는 정지 판정 구조 중 근거와 시간 예산이 준비된 후보를 고른다.
- **기존에 고정한 Stage 점수까지 변함:** 성능 해석을 멈추고 ZIP 코드 차이·시간·폴백·환경을 확인한다. 원인 해결 전 해당 파일을 최고점으로 병합하지 않는다.

한 계열의 대표 후보 두 개가 공식 평가에서 모두 지고 추가 독립 근거가 없으면 우선순위를 내린다. 이는 제출 예산 배분 규칙이며 그 계열이 불가능하다는 증명이 아니다. 수치를 촘촘하게 바꾸는 탐색은 그 축에서 실제 이득과 넓은 안정 구간이 확인된 뒤에 한다.

## 슬롯을 쓰기 전의 통과 조건

1. **실험 카드:** 기준 ZIP SHA, 바꿀 함수/설정 한 축, 예상되는 출력 변화, 비교 대상, 채택/보류 조건을 결과 보기 전에 기록한다.
2. **실제 ZIP 확인:** 압축 해제 사본으로 실행한다. 바꾸지 않은 Stage는 코드·설정과 공개 예측을 비교한다. ‘파일명만 바꾼 실험’을 막는다.
3. **영상별 진단:** 변경 행 수, 진입 추적 발동/대체 비율, 클래스 비율, 시간, 모델 폴백을 공개 자료에서 확인한다. 출력 분포만 보고 정답 분포를 추정하거나 거기에 맞추지 않는다.
4. **형식·경계:** 빈/짧은 입력, 모든 디코딩 프레임, 유효한 번호/범주, CPU 대체, 오프라인 가중치 로딩을 확인한다.
5. **시간:** 실제 ZD 서버 시간·로그를 먼저 확보한다. 무거운 후보는 스테이지별 비용을 측정하고 넉넉한 여유가 있는 경우에만 제출한다. 다른 파일을 처리한 시간 때문에 해당 파일의 예측을 바꾸는 방식으로 시간을 맞추지 않는다.
6. **로컬 점수의 위치:** 공개 점수는 버그 발견과 후보 준비에 사용한다. 공개 승리를 공식 승리로 쓰지 않는다. 같은 공개 세그먼트에서 수십 번 골랐다면 그 세그먼트는 더 이상 미사용 검증셋이 아니다.

## 더 큰 고점을 위한 병행 작업

소거만 하면 현재 규칙 주변의 작은 개선에 머물 수 있다. 매일 슬롯은 단기 실험에 쓰되, 개발 시간의 일부는 새 증거를 얻는 데 쓴다.

- **Stage 2:** 별도 공개 사고영상에서 실제 접촉·차선 진입·화면 방향·회피 공간을 같은 정의로 주석한다. 현재 5개 공개 영상의 미표기 세 항목을 정답처럼 쓰지 않는다. 교차로·끼어들기·추돌 등 사건 유형을 나누고, 같은 원본 영상의 조각은 동일 분할에 둔다.
- **Stage 3:** 정차→출발·제동→정지·지속 회전이 포함된 주행 자료와 실측 신호를 확보한다. 가속도·조향 임계값은 주최 측 정의가 확인된 범위와 대리 정의를 구분한다. 차량/주행 세션 단위로 나누고 마지막 확인용 세트는 후보 선택에 반복 사용하지 않는다.
- **규칙과 학습 비교:** 충분한 주석이 생기면 가벼운 시계열 학습 모델을 현재 규칙과 비교한다. 데이터가 부족한 채 모델만 크게 바꾸는 것과 구분한다.
- **결합:** 단독으로 이긴 모듈도 다른 모듈과 합치면 같은 점수를 보장하지 않는다. 새로운 조합은 공식 평가를 거친 뒤에만 최고점으로 표시한다.

남은 제출 가능일이 D일이면 이론상 최대 슬롯은 3D이지만 마감일의 제출 가능 시간·초기화 시점에 따라 달라진다. 마감이 가까워지면 새 대형 구조보다 재현·최종 선택·동봉 파일 점검에 시간을 배분한다. 대회 원문 사본에 연도 오기가 있어 실제 일정을 확인하기 전 특정 날짜까지 실험 가능하다고 확정하지 않는다.
