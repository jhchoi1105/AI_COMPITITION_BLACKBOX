# 블랙박스 영상 기반 지능형 고의사고 분석 AI — 쉬운 요구사항 정리

## 한 문장으로

블랙박스 영상을 넣으면 **재촬영 영상인지**, **사고가 언제·어떻게 났는지**, **차가 가속·감속·조향을 어떻게 했는지**를 자동으로 내놓는 프로그램을 `submit.zip` 하나로 제출하는 대회다.

## 반드시 해야 하는 일

| 단계 | 프로그램이 해야 할 일 | 반환 열 |
|---|---|---|
| Stage 1 | 영상이 원본인지, 다른 화면을 다시 촬영한 것인지 분류 | `ID`, `answer` (`ORIGINAL` / `RERECORDED`) |
| Stage 2 | 충돌 프레임, 끼어든 프레임, 회피 공간, 진입 방향 추정 | `ID`, `collision_frame`, `entry_frame`, `evasion_space`, `entry_side` |
| Stage 3 | 주행 중 각 샘플의 가감속·조향 상태 분류 | `ID`, `sample_index`, `accel_label`, `steer_label` |

`inference.py` 최상위에는 아래 함수 세 개가 정확한 이름으로 있어야 한다. 각 함수는 위 열을 가진 `pandas.DataFrame`을 반환한다.

```python
def predict_stage1(data_dir, model_dir): ...
def predict_stage2(data_dir, model_dir): ...
def predict_stage3(data_dir, model_dir): ...
```

## 점수에서 특히 조심할 점

- Stage 1은 두 클래스의 F1을 똑같이 보는 **Macro-F1**이다. 한쪽만 계속 찍으면 낮다.
- Stage 2의 프레임 번호는 내부적으로 시간으로 바꿔 정답 시간과 비교하며, 정답과 **±0.3초 이내**여야 한다. 결측치, 음수, 영상 범위 밖 프레임, 허용하지 않는 범주는 전부 오답이다.
- Stage 2의 충돌은 “위험해 보이기 시작한 때”가 아니라 **두 차량이 실제 접촉한 프레임**이다. 진입은 피해차량이 영상에 처음 보인 때가 아니라 **피의차량 차선에 처음 들어온 프레임**이다.
- `entry_side`는 도로의 방위가 아니라 블랙박스 **화면 기준**이다. 화면 왼쪽에서 들어오면 `LEFT`, 오른쪽이면 `RIGHT`다.
- Stage 3은 비공개 평가에서 10Hz다. 디코딩 프레임 수와 `sample_index` 수가 같으므로 0부터 마지막 프레임까지 **모든** 인덱스를 빠짐없이 반환해야 한다. 정지(`STOPPED`) 상태의 조향은 점수 계산에서 빼지만, 제출 파일에는 모든 샘플의 `steer_label`이 있어야 한다.
- 공개 데이터의 Stage 2 `t_entry`, `evasion_space`, `entry_side`는 모두 `-1`이다. 이것은 학습 정답이 아니라 **미표기**로 다뤄야 한다.

## 서버 제약: 여기서 실패하면 점수가 없다

- 제출물: 최상위에 `inference.py`, `requirements.txt`가 있는 `submit.zip`.
- 설치 10분 이내, Stage 1~3 전체 추론 60분 이내.
- ZIP 10GB 이하, 압축 해제 후 32GB 이하.
- 평가 서버는 인터넷이 막혀 있다. 가중치·코드는 ZIP에 미리 넣어야 하며, `weights=None`으로 구조를 만들고 저장 가중치를 읽는 방식이 안전하다.
- 서버 사양은 NVIDIA L40S(44.7GiB VRAM), 7 vCPU, RAM 60GB다.
- Python만 사용 가능하며 CSV는 UTF-8이어야 한다.
- 하루 제출 횟수는 최대 3회다.

## 현재 폴더에서 확인한 사실

| 항목 | 확인 결과 | 의미 |
|---|---|---|
| Stage 1 공개 라벨 | 원본 5개, 재촬영 5개 | 10건이라 단순 검증 수치는 매우 불안정하다. |
| Stage 1·2 영상 | 각 5초, 1280×720, 10fps, 50프레임 | 샘플 영상은 형식 확인·스모크 테스트용으로는 좋다. |
| Stage 2 공개 라벨 | 5건, 충돌 프레임 30·30·31·32·41만 표기 | 충돌시점 외 과업은 이 데이터만으로 지도학습할 수 없다. |
| Stage 3 공개 라벨 | 5개 영상, 50행(영상당 10개 지점) | 가속은 CONSTANT 30 / ACCELERATING 9 / DECELERATING 8 / STOPPED 3으로 불균형이다. |
| Stage 3 조향 라벨 | STRAIGHT 40 / LEFT 5 / RIGHT 5 | 정확도만 보면 직진만 찍는 모델이 좋아 보일 수 있으므로 Macro-F1 검증이 필요하다. |
| 기본 노트북 | MViTv2-S, ResNet18, BiGRU의 3단계 베이스라인 | `EPOCHS=1`이 기본이며, 현재 폴더에는 학습 완료 `model/` 가중치가 없다. |

## 지금 있는 베이스라인의 역할

제공 노트북은 형식 확인용 출발점이다. Stage 1과 3은 MViTv2-S, Stage 2는 ResNet18 특징과 BiGRU를 쓴다. 하지만 공개 예제가 너무 작고 학습 기본값도 1 epoch라서, 그 결과 하나만으로 순위를 기대하면 안 된다. 특히 Stage 2의 세 가지 미표기 항목은 별도 합법 데이터와 주석 전략이 필요하다.

## 금지선과 안전선

- 비공개 평가 데이터를 추가 학습, 파인튜닝, pseudo-labeling, 다른 파일 정보로 보정하는 일은 금지다.
- 파일 하나의 예측은 다른 평가 파일의 정보에 의존하면 안 된다.
- 법적으로 쓸 수 있는 공개 사전학습 모델·외부 데이터는 가능하지만, 2차 평가에서는 사용한 모든 요소의 출처를 밝혀야 한다.
- 모든 제출 전에는 빈 영상 폴더, 짧은 영상, 여러 확장자, GPU 없음 오류가 아닌 정상 처리 여부를 확인한다.

## 이 폴더의 오늘 제출물

`submissions/` 아래에는 가중치·인터넷 없이 동작하는 초기 탐색용 3개 제출물이 있다. 세 파일은 업로드용 ZIP으로도 만들며, 서로 다른 가설로 하루 3회 제한을 활용한다. 세 ZIP은 Stage 2에서 파일명 숫자를 그대로 제출하고, Stage 3에서 디코딩된 모든 프레임에 0부터 연속된 `sample_index`를 부여한다. 이는 우승 모델이 아니라 **평가 파이프라인 통과와 어떤 Stage가 병목인지 확인하기 위한 기준선**이다.
