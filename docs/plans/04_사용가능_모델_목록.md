# 사용 가능한 모델 목록 (2026-08-27 확인)

평가서버 사전설치 패키지(`torch 2.8.0` / `torchvision 0.23.0` / `timm 1.0.15` / `transformers 4.57.6` / `ultralytics 8.3.170`)를 실제로 설치해 확인한 결과다. "확인" 표시는 로컬에서 직접 열거·생성해 본 것이고, 라이선스는 원본 모델 카드를 직접 조회했다.

## 0. 먼저 알아야 할 제약

| 제약 | 의미 |

## 2. Stage 3 — 즉시 교체 가능한 것 (격차 0.316, 전체의 36%)

### RAFT (KITTI 파인튜닝) — 최우선

현재 Stage 3은 `cv2.calcOpticalFlowFarneback`로 광류를 구한다. torchvision에 **주행 장면으로 파인튜닝된 RAFT 가중치**가 들어 있다.

```
Raft_Large_Weights.C_T_SKHT_K_V1 / _V2   <- K = KITTI(주행 장면) 파인튜닝
Raft_Large_Weights.C_T_SKHT_V1 / _V2     <- Sintel/HD1K/Things
Raft_Small_Weights.C_T_V1 / _V2
```

| 모델 | 파라미터 | fp32 | 비고 |
|---|---:|---:|---|
| `raft_large` | **5.3M** | **21MB** | KITTI 가중치 있음. 사전설치·BSD-3 |
| `raft_small` | 1.0M | 4MB | 시간이 부족할 때의 대안 |

Farneback 대비 이득이 큰 이유: 우리 현재 특징은 **전체 프레임 광류의 중앙값**인데, 이는 하늘·정적 영역에 오염된다. RAFT의 밀집 광류는 도로 평면 ROI, 소실점 근처 요레이트, 발산(divergence) 기반 속도 대리값을 분리해 낼 수 있다.

### 단안 깊이 — Depth Anything V2 **Small** (Apache-2.0, 24.8M)

깊이를 얻으면 광류를 **스케일 있는 자기운동**으로 바꿀 수 있다. 지난번 실패한 "절대 문턱 정지 판정"이 실패한 이유가 바로 스케일이 없었기 때문이다. 깊이 + 광류면 실제 속도 대리값이 나온다.

**Large/Base는 CC-BY-NC이므로 Small만 쓴다.**

### 영상 분류 백본 (가감속·조향 헤드 학습용)

전부 torchvision 사전설치, BSD-3, Kinetics-400 사전학습.

| 모델 | 파라미터 | fp16 |
|---|---:|---:|
| `s3d` | 8.3M | 17MB |
| `mc3_18` | 11.7M | 23MB |
| `swin3d_t` | 28.2M | 56MB |

## 3. Stage 1 — 격차 0.485, 전체의 56%

### 먼저: 아키텍처보다 입력 파이프라인이 중요하다

우리가 직접 측정한 사실이다. 같은 특징이 **256폭 축소에서 신호/잡음 0.07, 원본 해상도에서 1.47**이었다. ImageNet 백본의 표준 전처리는 224로 리사이즈하는데, 그러면 판별 신호가 **모델에 들어가기 전에 사라진다.**

따라서 어떤 백본을 쓰든 **원본 해상도 패치 단위 분류 + 집계**로 가야 한다. 프레임당 256×256 패치 N장을 뽑아 각각 분류하고 평균한다.

### 백본 후보 (timm, 전부 사전학습 가중치 존재 확인)

| 모델 태그 | 파라미터 | fp32 | 근거 |
|---|---:|---:|---|
| `legacy_xception.tf_in1k` | 22.9M | 91MB | FaceForensics++ 등 **딥페이크/포렌식 표준 백본**. 저수준 아티팩트에 강하다 |
| `tf_efficientnet_b4.ns_jft_in1k` | 19.3M | 77MB | DFDC 우승 계열 백본 |
| `tf_efficientnet_b0.ns_jft_in1k` | 5.3M | 21MB | 패치 다수 처리 시 속도 확보용 |
| `convnext_tiny.fb_in1k` | 28.6M | 114MB | 일반 강백본 |

### 사전학습 모델이 아닌, 더 중요한 요소

재촬영 판별은 **저수준 신호 처리 문제**다. 사전학습 분류기보다 아래 두 가지가 효과가 클 가능성이 높다.

1. **고역통과 전단(front-end)** — SRM 필터 뱅크 또는 Bayar 구속 합성곱을 첫 층에 고정/학습으로 넣는다. 스테가날리시스·위변조 검출에서 표준이며 코드 30줄 수준이다. 사전학습 가중치가 필요 없다.
   **채택.** F·I 결과로 hf/coarse 비율의 판별력(a+b−1)이 +0.31임이 확인됐고, 임계값만 옮겨 도달할 상한은 약 0.682다. 1위 0.92814까지의 나머지 0.31은 이 전단처럼 **특징 자체를 바꾸는** 처방에서 나와야 한다.
2. **DCT/블록 아티팩트 도메인** — 재인코딩은 8×8 블록 경계와 양자화 흔적을 남긴다. 화면 재촬영은 재인코딩을 반드시 동반한다.

### 학습데이터는 자체 생성이 가능하다

Stage 1은 **세 Stage 중 유일하게 데이터 병목이 없다.** 원본 주행 영상에 재촬영을 시뮬레이션하거나, 실제로 모니터를 재촬영하면 라벨이 무한히 생긴다.

**단, 우리가 이미 데인 부분이 있다.** 공개 예제의 합성 재녹화는 고주파를 *늘리는* 방향이었는데 실제 평가 데이터는 반대로 보인다(F 제출 0.2682). 시뮬레이션을 만들 때 **광학 흐림·초점 손실·디스플레이 재구성 필터·재인코딩을 반드시 포함**해야 하며, 가능하면 실제 모니터 재촬영 데이터를 섞어야 한다. 시뮬레이션만으로 학습하면 같은 부호 오류를 반복한다.

## 4. Stage 2 — 격차 0.071, 전체의 8% (비용을 묶을 것)

격차가 작으므로 **새 모델을 얹는 투자는 권하지 않는다.** 다만 항목별로 원리적으로 맞는 도구는 아래와 같다.

| 항목 | 도구 | 비고 |
|---|---|---|
| `evasion_space` (회피 공간) | **Depth Anything V2 Small** (Apache-2.0) + 도로 영역 분할 | "피할 공간이 있었는가"를 깊이로 직접 재는 것이 유일하게 원리적인 접근 |
| `entry_frame` / `entry_side` | 차량 검출 + 추적 후 충돌 프레임에서 **역추적** | `ultralytics`(AGPL 주의) 또는 torchvision `fasterrcnn_resnet50_fpn_v2` / `maskrcnn_resnet50_fpn_v2` (BSD-3) |
| 차량 마스크 시간 추적 | SAM2 / EdgeTAM (transformers에 있음) | 가중치 라이선스 미확인 |
| 도로/차선 분할 | torchvision `deeplabv3_resnet50`, `fcn_resnet50` (BSD-3) | 차선 전용 사전학습 모델은 사전설치 패키지에 없다 |

추적기 의존성인 `lap`, `filterpy`가 사전설치되어 있다 — ByteTrack/BoT-SORT를 쓰라는 신호로 읽힌다.
